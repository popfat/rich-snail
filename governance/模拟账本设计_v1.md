# 模拟账本设计（v1 · 单标的极简账本）

> 工作包：B6（WP-B06-02 配套）｜ 依据：核心数据契约 §2.7a（所有者 R2 决策口径）
> 日期：2026-11-24 ｜ 状态：draft（S2 首次 paperwalk/backtest 运行时启用）
> 目的：让 paperwalk/backtest 的每次模拟决策可计算利润，用于**决策质量评估**（评价方案 L3b/L4 准备），不做交易 App 级簿记。

---

## 1. 账本口径（契约已定，不再重复决策）

| 项 | 约定 |
|---|---|
| 标的 | 沪深300ETF（510300.SH），单一标的；行情源 `fund_daily`（2026-11-24 实测可用，见 snapshots/b1 探测报告） |
| 行动空间 | `enter / exit / hold / observe`；observe 必填 `reason ∈ {no_signal, abstain_condition, discipline, risk_off}` |
| 仓位 | 二值 0/1（满仓进出） |
| 成交 | 决策日 T 14:50 → 按 **T 日收盘价**模拟成交；14:50 估计价仅展示不入账 |
| 交易规则 | 遵循 510300 实际规则（T+1：当日买入次日方可卖出），在配置中显式声明 |
| 成本 | 佣金+滑点常数，**初值待所有者确认（O2）**，写入配置并版本化 |
| 记账 | 日频持仓标志 × 标的日收益 → NAV 序列 |

## 2. 数据结构

### 2.1 账本配置 `ledger_config`（版本化，变更产生新版本）

```yaml
config_version: 1
instrument: 510300.SH
instrument_data_source: fund_daily   # 2026-11-24 实测 OK
position_model: binary               # 0/1
execution: close_of_decision_day     # T 日收盘价
trade_rule: T+1
cost:
  commission_rate: TBD               # O2 待确认（如万 1）
  slippage_rate: TBD                 # O2 待确认（如万 5）
  min_commission: TBD                # 若有
benchmark: buy_and_hold_510300       # 买入持有基准 NAV
created_at: YYYY-MM-DD
note: 成本初值未确认前，账本输出标注 cost_assumption=TBD，收益数字为毛口径
```

### 2.2 每日账本记录 `ledger_daily`（追加写，不回改）

| 字段 | 说明 |
|---|---|
| trade_date | 交易日 |
| ptr_id | 当日 PaperTradeRecord（无决策的日期为空——paperwalk 每日 14:50 必有记录，缺失即异常） |
| action / reason | 行动与 observe 原因 |
| target_position | 0/1（当日决策后的目标仓位） |
| executed_price | 成交价（T 收盘；enter/exit 当日必填） |
| cost_amount | 当日成本（按配置） |
| position_eod | 收盘后持仓 0/1 |
| daily_return | 当日收益（持仓×标的涨跌−成本摊入） |
| nav | 净值（初始 1.0） |
| benchmark_nav | 买入持有净值 |
| config_version | 账本配置版本 |

### 2.3 与契约对象的挂接

- `PaperTradeRecord.outcome`：由 `ledger_daily` 自动生成追加（持有期收益、期间最大回撤、与判断差异），带 `recorded_at`；
- `Experiment`（backtest）：在同一账本配置上对历史区间重放决策序列，产出 NAV 与对照（baseline=buy_and_hold_510300 及实验声明的其他基准）；
- `DecisionLog.outcome`：引用对应 PTR 的 outcome 摘要。

## 3. 评价输出（只记录，S5 前不设通过线）

- 累计收益、年化、最大回撤、胜率（按 enter→exit 回合计）、换手次数、成本占比；
- 相对买入持有基准的超额；
- 按 regime 格/信号档的失败切片（与 HYP/REG 卡联动）。

## 4. 反作弊与边界

- NAV 毛口径（成本 TBD）不得用于任何晋级判断；
- backtest 的 evaluation 区间结果在设计冻结前禁读（契约 §2.8）；
- paperwalk 期间之后的信息不得回灌历史实验；
- 账本不回改：配置变更只影响变更日之后（旧 NAV 保留，新 NAV 另起序列并关联旧配置版本）。
