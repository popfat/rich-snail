# 核心数据契约（v3 · 数据字典）

> 工作包：WP-B00-03 ｜ 依据：Roadmap §2（跨分支核心数据契约）、知识库文档 §4/§9；2026-11-22 所有者 Q2、R2 决策
> 日期：2026-11-22 ｜ 状态：draft，待 G0 人工审核。审核通过后，**跨分支字段变更必须先改本契约再改实现**（Roadmap §11.3）。
> v3 变更：PTR 落地"单标的极简账本"口径（沪深300ETF、二值仓位、T收盘成交、成本常数化、日频 NAV）；backtest 复用同一账本。
> 本文件只定义 S0 最小字段与统一规则；各分支可在实现时扩展字段，但不得删减本契约字段，不得绕过版本与时间信息。

## 1. 统一约定

### 1.1 ID 规则

| 对象 | 前缀 | 格式示例 | 说明 |
|---|---|---|---|
| MarketSnapshot | `MS` | `MS-20261122-daily` | 数据快照 |
| FeatureSnapshot | `FS` | `FS-20261122-portrait-v1` | 指标快照 |
| KnowledgeCard | 按类型：`SRC/CON/FEA/REG/HYP/PBP/CAS/BEH/EXP/DEC` | `HYP-000001` | 知识库文档 §4.1 |
| NewsEvent | `NE` | `NE-20261122-0001` | S4 前不启用 |
| EvidencePack | `EP` | `EP-20261122-0001` | 检索证据包 |
| AnalysisReport | `RPT` | `RPT-20261122-v1` | 盘后报告 |
| DecisionLog | `DEC` | `DEC-20261122-0001` | 决策日志 |
| PaperTradeRecord | `PTR` | `PTR-20261122-0001` | 模拟交割记录（paperwalk） |
| Experiment | `EXP` | `EXP-000001` | 实验（与知识卡 EXP 同空间） |
| ImprovementProposal | `IP` | `IP-000001` | S6 前不启用 |

规则：ID 全局唯一、不可复用；对象修改产生新 `version`，ID 不变；删除只允许走 `deprecated/retired` 状态，不物理删除。

### 1.2 时间语义（六时间，防未来函数）

所有承载外部信息的对象必须区分（知识库文档 §9）：

| 字段 | 含义 |
|---|---|
| `event_time` | 事件发生时间 |
| `publish_time` | 信息对外发布时间 |
| `available_time` | 系统/策略当时实际可用时间 |
| `ingest_time` | 本项目收录时间 |
| `knowledge_created_at` | 知识形成时间（仅知识对象） |
| `knowledge_updated_at` | 知识修改时间（仅知识对象） |

规则：历史回放与检索一律带 `as_of`，只读 `available_time <= as_of` 且当时存在的版本；无法确认可见时间的资料标记 `time_risk=true`，不用于严格历史验证；日期不知道填 `unknown`，不得猜测。

### 1.3 通用字段（每个对象）

`id`、`version`、`created_at`、`updated_at`、`status`、`derived_from[]`（输入对象引用）、`provenance`（human/external/llm/hybrid）。

### 1.4 统一红线（Roadmap §2）

1. 每个派生对象能追溯输入对象（`derived_from` 必填，无输入时说明）。
2. 当时记录与事后结果分离：事后信息只能以**追加关联**写入（如 DecisionLog 的 `outcome` 区），不回改当时字段。
3. LLM 输出不得替代原始行情、原始新闻和真实实验结果。
4. 报告中禁止引用未启用字段（如画像占位符 north_flow、rate10y）与未启用卡片类型。
5. **本项目不实现指标计算**（所有者 D8 决策）：FeatureSnapshot 与指标卡只登记/引用既有项目（section_heat、wind_vane、rich_trend）的计算产物与公式版本；发现"应该有但不存在"的指标，只提交 ImprovementProposal 候选（L1 级）报告所有者，不在本项目内实现。

## 2. 对象最小字段

### 2.1 MarketSnapshot（B1）

| 字段 | 说明 |
|---|---|
| id / version / created_at | 通用 |
| snapshot_date | 数据时点（交易日） |
| source | 数据源（tushare 接口名 / akshare / MySQL 表） |
| universe | 覆盖对象（如 全A、90个THS行业、000001.SH） |
| fields[] | 实际字段清单与单位（金额单位必须标注：元/万元/亿元） |
| raw_ref | 原始数据引用（文件路径/表名+主键范围/请求参数） |
| event_time / publish_time / available_time / ingest_time | 六时间中适用的四个 |
| quality_status | `ok / partial / failed / suspect` + `quality_note`（如"margin 仅 SSE 已更"） |

### 2.2 FeatureSnapshot（B1）

| 字段 | 说明 |
|---|---|
| id / version / created_at | 通用 |
| feature_id | 指标ID（如 `portrait.leverage_pct`） |
| formula_version | 公式与参数版本（指向实现 commit 或配置哈希） |
| input_snapshot_ids[] | 输入 MarketSnapshot 引用 |
| params | 参数（如分位窗口 1250/250 日） |
| values_ref | 计算结果引用（路径/表），关键值可冗余存 `values_digest` |
| computed_at | 计算时点 |
| anomaly_status | `ok / insufficient_history / failed` + 说明（对齐 RobustZ"样本不足置 NULL"惯例） |

### 2.3 KnowledgeCard（B2）

采用知识库文档 §4.3 YAML 元数据 + §4.4 正文结构，S0 固定要点：

- 必备元数据：`id、type、title、status、version、origin、created_at、updated_at、source_ids[]、market_scope、universe、timeframe、horizon、regime_scope[]、decision_role、evidence_grade、source_time、available_time、related_ids[]、tags[]`；
- `status` 状态机：`draft → pending_review → pending_validation → observing → active → deprecated → retired`，另设 `rejected`（负面保留）；
- 关系字段：`derived_from / supports / contradicts / refines / supersedes / validated_by / evidenced_by / used_in / generated_by`；**冲突关系不得被相似度去重删除**；
- 缺失字段填 `unknown` 或入 `open_questions`，不得补造；`regime_scope` 为空=尚未定义，≠适用全部。

### 2.4 NewsEvent（B4）— **S0—S3 不启用**

保留契约占位：`event / event_time / publish_time / available_time / source / dedup_group / impact_hypothesis / verification_status`。首期报告不含新闻区。

### 2.5 EvidencePack（B3）

| 字段 | 说明 |
|---|---|
| id / created_at | 通用 |
| query_context | `as_of、universe、timeframe、horizon、decision_type、market_regime、query`（知识库文档 §11.1） |
| active_knowledge[] | 正式知识引用（含版本） |
| observing_knowledge[] | 仅观察知识（必须带状态标注） |
| counter_evidence[] | 反例/失败案例；**无反例时显式写"尚未收集"，不得省略该字段** |
| conflicts[] | 冲突知识对 |
| invalidation_conditions[] | 失效条件 |
| limitations | 数据/时间/版本限制 |
| citations[] | 来源 ID + 精确定位（路径+标题/段落/行号至少一种） |

### 2.6 AnalysisReport（B5）

| 字段 | 说明 |
|---|---|
| id / version / created_at | 通用 |
| mode | `paperwalk / backtest`（v2 新增，必填） |
| trade_date / as_of | 报告对应交易日与生成时点 |
| facts[] | 事实区，每项含 `value、source_snapshot_id、feature_version、quote_type`（close / intraday_estimate，14:50 盘中值必须标 `intraday_estimate`） |
| observations[] | 状态观察（引用画像/信号快照） |
| conflicts[] | 指标/知识冲突（双方引用） |
| interpretations[] | 分栏：`external_view / personal_experience / llm_hypothesis / experiment_result`，各带证据状态 |
| risks[]、invalidation_conditions[]、no_trade_conditions[] | 风险区 |
| evidence_gaps[] | 缺口区 |
| abstention | `{triggered: bool, conditions_hit: [], statement}` |
| simulated_decision | paperwalk 必填：当次模拟行动/不行动与依据引用；**写入后不可改写**；backtest 模式置 `not_applicable`（实验行动由 Experiment 承载） |
| input_versions | 数据快照、指标版本、知识版本、EvidencePack ID、模型ID、提示词版本、工具版本 |
| llm_free_numbers | 固定为 `true`：数值只能来自 facts 引用的确定性结果 |

### 2.7 DecisionLog（B6）

| 字段 | 说明 |
|---|---|
| id / created_at / as_of | 通用；**当时快照不可改写** |
| mode | `paperwalk / backtest` |
| input_refs | 当时输入：快照、证据包、报告 ID 及全部版本 |
| report_id | 关联 AnalysisReport |
| action | 人工行动或"不行动"（paperwalk 下为模拟行动） |
| human_feedback | 人工反馈（正确/错误/存疑 + 备注） |
| outcome | 事后结果，**只能追加**，带 `recorded_at`，不回改以上字段 |

### 2.7a PaperTradeRecord（B6，paperwalk 专属，v2 新增；v3 增加单标的极简账本口径）

模拟交割记录是"实践→知识"反馈闭环的核心载体：让每次模拟决策像真实交割单一样可复盘、可沉淀（所有者 Q2 决策）。

**账本口径（v3，所有者 R2 决策：做到"能算利润"为止，不做交易 App 级簿记）**：

| 账本设计 | 约定 |
|---|---|
| 标的 | 单一标的：**沪深300ETF（510300）**——与大盘研究对象对齐、无个股/行业风险、流动性好；每标的独立账本，不做组合 |
| 行动空间 | `enter`（买入至满仓）/ `exit`（清仓）/ `hold`（有仓维持）/ `observe`（不动作，附 `reason`：`no_signal` 无信号 / `abstain_condition` 触发弃权条件 / `discipline` 有信号但纪律性不交易 / `risk_off` 风险规避）——`no_trade` 已并入 observe（所有者 D7 决策） |
| 仓位模型 | 二值（0/1 满仓进出）；**不引入部分仓位、均价、浮盈簿记**——仓位管理是未来版本，需另行立项 |
| 成交假设 | T 日 14:50 决策 → 按 **T 日收盘价**模拟成交（14:50 估计价仅展示不入账）；交易规则遵循该 ETF 实际规则（T+1），在账本配置中显式声明 |
| 成本假设 | 佣金+滑点以常数写入账本配置并**版本化**；初值待所有者确认（不虚构费率） |
| 记账方式 | 由每日持仓标志 × 标的日收益生成**日频模拟净值（NAV）序列** → 累计收益、最大回撤、胜率、换手次数；无逐笔交割簿 |

| 字段 | 说明 |
|---|---|
| id / created_at | 通用 |
| decision_id / report_id | 关联的 DecisionLog 与 AnalysisReport（当时引用，含版本） |
| trade_date / action_time | 模拟决策日期与时点（14:50，标注盘中/收盘口径） |
| instrument | 标的（默认 `510300`，账本配置引用） |
| simulated_action | `enter / exit / hold / observe` + `reason`（observe 必填枚举） |
| rationale_refs[] | 依据引用（报告分区、KnowledgeCard ID） |
| constraints | 当时声明的风险约束与不交易条件 |
| outcome | 事后结果（由 NAV 序列自动追加：持有期收益、期间事件、与判断的差异），**只能追加**，带 `recorded_at`；多个观察窗口可多条追加 |
| review_note | 复盘笔记（人工或 LLM 草稿，标注 provenance）；复盘结论只能进入候选队列，不得自动成为正式知识 |

规则：PTR 的记录口径与真实交割单对齐（当时信息/事后结果分区），为后续研究"执行质量"和 RSI 提供数据前提；paperwalk 的 NAV 只作**决策质量评估工具**（评价方案 L4 准备），**不等于实盘表现，不构成策略授权**。

backtest 模式复用同一账本口径（同一标的、同一成本与成交假设、同一时间切分），保证历史回测与前向 paperwalk 可比。

### 2.8 Experiment（B6，与知识卡 EXP 同型）

最小字段：`id / hypothesis_ref / question / baseline / data_snapshot_ids[] / time_split / results（真实结果，含负面） / failure_slices[] / limitations / conclusion（支持/不支持/证据不足） / reproduction_ref（代码+配置引用） / all_attempts_ref`。

`time_split`（v2 强化，backtest 模式必须）：按时间顺序显式声明三个区间——

| 区间 | 用途 | 硬规则 |
|---|---|---|
| `train` | 规律发现、参数候选 | 可用 |
| `validation` | 调参与候选筛选 | 可用；多次使用须记录尝试次数 |
| `evaluation` | 最终检验 | **实验设计冻结前不得读取其结果**；只用于报告结论 |

切分点、窗口长度写入实验卡并版本化；所有区间数据须通过 as_of 可见性校验。

规则：不得只保存最优参数；结果不支持也入库；结论不得超出样本范围。

### 2.9 ImprovementProposal（B8）— **S6 前不启用**

保留契约占位：`target / problem_evidence / diff / experiment_ref / risks / rollback / review_status`。

## 3. 存储与落位（逻辑目录）

遵循知识库文档 §5，落位到本项目（S1 由 B2 实现，本轮只定映射）：

```
rich-snail/
├── governance/          # B0：任务书、契约、评价、看板、门禁（本轮）
├── inventory/           # B0/B2：资产与来源清单（本轮）
├── knowledge_base/      # B2：01_sources … 10_archive（S1 建，原文只读引用）
├── snapshots/           # B1：MarketSnapshot / FeatureSnapshot（S1 建）
├── evidence/            # B3：EvidencePack（S2 建）
├── reports/             # B5/B7：AnalysisReport 与运行记录（S2 建）
├── decisions/           # B6：DecisionLog（S2–S3 建）
├── experiments/         # B6：Experiment（S1 起，先实验计划）
└── indexes/             # B3：可重建派生索引（S2 建；不是真相源）
```

原始资料**不复制**进本项目：`01_sources/` 只存只读引用（路径 + 校验值 + 定位信息）。
